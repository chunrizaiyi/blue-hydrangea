## 三、主要验证内容

### 1. AI 请求与异常处理

今日花语的合法返回、请求体字段、五类 HTTP 错误（401、402、403、429、500）、取消旧请求、空白及超长输入、空结果均使用本机模拟接口检验。情绪解语检验了完整结构化卡片、先提问后分析的两轮返回，以及缺少必填字段时的拒绝行为。测试断言请求体只包含当前输入，不自动夹带回忆、纪念日等其他本地记录；错误提示不包含服务端原始响应。所有测试密钥均为无效占位值。

上述断言只适用于列出的模拟响应。真实服务可用性、模型生成质量、Android Keystore 密钥存取、网络中断、超时和危机场景内容，均未在本阶段验证。

### 2. 数据升级与持久化

使用一次性 SQLite 文件分别构造版本 5 的单图回忆、心情、专注记录和版本 7 的多图回忆。调用应用实际升级回调至版本 8 后，核对记录数量、单图迁入多图表、原多图顺序、心情备注、专注字段及旧信件表清理。另在独立数据库内验证回忆的新增、修改、重启式重新打开与删除，心情的连续新增、空备注修改与删除，以及专注记录的重复键去重。

数据库测试核对表结构、记录字段和图片路径顺序；所用路径不对应实际照片文件。正式 APK 覆盖安装后的文件可读性及手机存量数据保留情况，仍需真机验证。

### 3. 应用内流程

在本地 Android 16 模拟器中打开主应用，进入“我们的回忆”添加一条虚构文字记录，确认列表立即显示；进入“今天的心情”新增虚构备注，确认数据库写入和列表展示；再返回回忆页，确认记录仍在。测试结束时删除本次生成的两条虚构记录。该用例验证了页面导航、表单提交、列表刷新及跨页保留，但未覆盖图片选择、权限弹窗、删除确认、欢迎引导、后台计时或小米系统界面。

## 四、执行中出现的问题及处理

1. 首次模拟器构建因本机未设置 `JAVA_HOME` 而未进入测试。配置项目自带 JDK 17 后继续执行；此项属于环境准备问题，不计为产品缺陷。
2. 测试依赖的较新版本尝试从外部下载 Android SQLite 原生文件，下载连接中断，阻止了测试包构建。将测试专用依赖固定为 `sqflite_common_ffi 2.3.7+1`（使用 `sqlite3 2.9.4`）后，测试包成功构建安装。此调整避免测试工具影响日常 Android 打包。
3. 应用流程首轮在心情断言处失败：记录已保存，但测试脚本未滚动到屏幕下方的懒加载列表。增加数据库写入核对和列表滚动后复测通过。该失败属于用例定位不完整，未登记为产品缺陷。

上述三项均为环境或测试脚本问题，本阶段未记录产品缺陷。

复核时，在项目根目录安装 `pubspec.lock` 所锁定依赖，然后依次运行：

```powershell
flutter pub get
flutter test --no-pub -r expanded
flutter analyze --no-pub
$env:BLUE_HYDRANGEA_ISOLATED_TEST = '1'
flutter test --no-pub -r expanded integration_test/garden_core_flow_test.dart -d <隔离的Android模拟器ID>
```

最后一条命令会安装独立包名的测试包并写入两条虚构记录。本阶段结果仍以隔离模拟器为准；2026 年 9 月 26 日增加了包名校验，复核当前测试脚本时必须设置上述隔离变量。真机升级、权限、后台计时、在线服务和系统通知不属于本阶段已通过项目。
