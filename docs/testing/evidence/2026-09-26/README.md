# 2026 年 9 月 26 日执行证据索引

本目录保存小米 14 真机检查与电脑端回归的原始记录。结论及覆盖边界分别见[真机执行报告](../../07-阶段三小米14真机执行报告.md)和[全量用例覆盖明细](../../08-全量用例覆盖明细.md)。

## 文件用途

| 文件类型 | 内容 | 使用方式 |
| --- | --- | --- |
| `xiaomi14-*.log` | 测试驱动输出、断言、系统操作时间及执行状态 | 与同名 JSON 对照查看，不能仅凭最后一条成功信息判断整轮通过 |
| `xiaomi14-*.json` | 执行环境、源码基线、时间、参数及退出码 | 退出码 0 表示该轮驱动成功结束；非 0 的原因需结合日志分析 |
| `xiaomi14-deadline-*.json` | 到点后的隔离包计时快照、息屏和安全锁状态 | 判断唤醒屏幕前是否已保存完成状态，不作为实际声学测量 |
| `host-regression-*.log` | 模型、数据、AI 模拟接口及资源检查输出 | 查阅每项测试及最终计数 |
| `host-analyze-*.log` | Dart 静态检查输出 | 只反映静态检查，不替代运行验证 |
| `host-checks-*.json` | 电脑端检查的起止时间、退出码及日志名称 | 区分初测与复测 |
| `*.png` | 独立测试应用前台截图 | 辅助复核布局；单张截图不证明动画流畅性 |

## 复核顺序

1. 核对执行报告中的产品源码基线与设备环境。
2. 根据报告链接读取执行日志及同名元数据，核对断言、时间和退出码。
3. 结合测试源码确认输入、预期结果和清理边界。
4. 阅读覆盖明细中的未完成步骤，区分完整用例、部分步骤和数据层验证。

初次失败、环境阻塞和复测成功的日志均予保留。测试材料为虚构文字、合成图片和无效密钥；设备序列号以 `xiaomi14` 替换。此替换仅用于隐私保护，不调整断言或执行结果。截图仅针对独立测试应用，不包含手机桌面、私人照片或正式包记录。

截图在公开前另行检查。`xiaomi14-followup-142909-calendar-countdown.png` 与 `xiaomi14-followup-142909-countdown-reset.png` 因包含系统浮动私人通知，已从公开证据目录移出并保留于本机排除上传的目录。原始日志中的截图事件保留，不将这些图片作为公开附件；同轮正计时与番茄钟日历截图，以及 13:38 轮次的倒计时重置截图可供布局复核。

文件校验清单由 `scripts/validate_test_evidence.py --write-manifest` 在执行结束后生成，用于核对文件完整性；它不替代测试结论，也不构成第三方认证。

本目录禁用 Git 自动换行转换，避免 Windows 与其他系统之间的转换改变文件哈希。原始日志自带的行末空格不作格式清理；代码和报告的格式检查单独执行。暂存后可通过 `--verify-index` 核对 Git 中的证据字节与清单是否一致。
